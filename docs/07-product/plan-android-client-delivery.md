# Android 客户端成品交付排期

> 基线日期：2026-09-09  
> 当前基线：五段式本地 Demo 已可生成 APK；Mobile API 配对与远端同步暂时下线。  
> 计划口径：以 1 名主开发持续推进估算，工程周期约 8 周；应用商店审核时间另计。

## 1. 交付目标

成品保留以下五段式结构：

```text
Today / Tools / + / Chat / Settings
```

最终交付应满足：

- Today 使用真实日历数据，支持查看、创建、编辑、完成和删除。
- `+` 支持 Note / Idea / Journal 快速记录，并能确认是否同步成功。
- Chat 连接 Persona，支持失败重试、会话恢复和清晰的在线状态。
- Tools 只承载已经实现、通过验收的工具，不放置虚假入口。
- Settings 提供外观、通知、同步、关于和安全的设备/会话管理。
- 支持浅色/深色、系统字体缩放、TalkBack、安全区域和横竖屏。
- 弱网和离线状态不会丢失用户已输入内容，也不会制造重复写入。
- 服务端写入继续经过 Application、Event、版本校验和持久化任务。
- 提供可安装 APK、版本说明、回滚包和可复现的构建记录。

不把向量检索、多 Agent、自主规划或新的长期 Memory 规则纳入本次 Android
交付。

## 3. 分阶段工作

### P0：Demo 收口

预计：2–3 个工作日。

工作内容：

- 删除 Today 页右上角当前仅作装饰的 Persona 星芒标志。
- 保留底部 `Chat` 作为唯一明确的 Persona 对话入口。
- 检查五段式导航状态保持、返回键和中央 `+` Bottom Sheet。
- 修正小屏、横屏、软键盘和底部手势区域遮挡。
- 清理看似可点击但没有行为的设置项；未实现功能显示为说明性状态。
- 建立稳定的 Debug APK 构建命令和产物命名。

人工交互：

- **必须**在至少一台真实 Android 手机上确认视觉密度、滚动和底部导航手感。
- **必须**确认删除星芒后 Today 顶部是否保留纯文字标题，或换成头像/状态入口。

退出标准：连续冷启动 10 次无崩溃，五个入口均可达，分享文本能正确打开 Capture。

### P1：产品与交互冻结

预计：2–3 个工作日。

工作内容：

- 确定中英文策略、最终产品名、图标和品牌文案。
- 明确 Tools 首发是否保持空状态；若不为空，只选择已有服务端能力。
- 确认 Today 的信息优先级、空状态、Demo 数据退出策略和事件点击行为。
- 定义 Chat 的会话展示范围、历史恢复和建议动作确认流程。
- 定义 Capture 保存成功、失败、草稿保留和重复提交反馈。
- 冻结 Settings 的首发项目，不在开发中持续增加入口。

人工交互：

- **必须**由产品负责人逐页确认范围和文案。
- **必须**完成一次 30–45 分钟的真机交互走查。
- 建议邀请 1–2 名非开发用户完成 Today、Capture、Chat 三个任务测试。

退出标准：形成不可歧义的页面/状态清单；之后新增能力进入下一版本，不插入本期。

### P2：连接与安全方案

预计：1 周。

当前配对仅从客户端流程下线，服务端 Bearer Token 合同仍保留。成品接入前必须
选择一种方案：

1. 恢复一次性配对码与设备 Token，适合私人部署和多设备管理。
2. 改用经产品确认的统一登录/OAuth 流程。
3. 保持完全本地 Demo，不交付远端 Chat、Capture 和 Calendar 写入。

禁止为了省略配对而开放匿名 Mobile API。

工作内容：

- 确定 Access Token、Refresh Token、撤销、过期和设备丢失处理。
- 明确 Cloudflare Access、Caddy 和 Persona API 的公网边界。
- 更新 `mobile-api-v1.md`、服务端 contract 和 Android 客户端状态机。
- 设计首次连接、重新认证、离线和会话失效体验。

人工交互：

- **必须**由用户/产品负责人选择认证方案。
- **必须**由部署负责人确认域名、HTTPS、Access 策略和测试环境。
- **必须**人工保管真实凭据；凭据不得写入仓库、截图或测试日志。

退出标准：威胁边界清楚，认证合同测试通过，未认证请求保持拒绝。

### P3：数据接入基础

预计：1 周。

工作内容：

- 恢复或重构 Mobile API Session，不让页面直接管理 Token。
- 接入 Bootstrap、Calendar、Capture、Chat，统一超时和错误模型。
- 恢复 Room/KSP 缓存生成链路，移除当前纯 Demo 的 Javac 构建规避配置。
- 建立 DTO 到本地模型的单向映射，忽略未知字段但不猜测缺失字段。
- 增加 API contract、Repository 和 ViewModel 测试。

人工交互：

- **必须**提供可用的测试服务端和测试设备身份。
- **必须**确认测试数据是否允许保留；真实私人数据默认不得进入测试证据。

退出标准：客户端可安全连接测试环境，Bootstrap 后可离线重开并展示最近缓存。

### P4：核心功能闭环

预计：2 周。

工作内容：

- Today：真实日期、今日重点、Upcoming、空状态和刷新状态。
- Calendar：事件详情、创建、编辑、完成、删除、提醒和 `409` 冲突恢复。
- Capture：Note / Idea / Journal、分享预填、草稿保护、幂等提交和结果反馈。
- Chat：消息发送、加载、失败重试、幂等 requestId 和会话恢复。
- Settings：主题、通知权限、同步状态、关于及经批准的会话管理。
- 所有服务端写入继续先进入 Event 或现有受管 Application 写入路径。

人工交互：

- **必须**确认 Calendar 删除/重复事件范围等不可逆选择的交互文案。
- **必须**检查 Companion 输出、失败反馈和隐私展示是否符合预期。
- **必须**用真实但可清理的测试数据完成一次端到端验收。

退出标准：Today、Calendar、Capture、Chat 四条核心路径均能在真实服务端完成。

### P5：离线、同步与提醒

预计：1 周。

工作内容：

- 定义离线只读、草稿和允许排队写入的明确边界。
- 恢复 WorkManager，同步任务具备网络约束、退避和幂等。
- 处理 Token 过期、请求超时、重复提交、`409` 和服务端 `5xx`。
- 验证设备重启、时区变化、应用升级后的本地提醒重建。
- 限制缓存内容、日志和通知文案中的敏感信息。

人工交互：

- **必须**在至少两台不同 Android 版本的真机上测试。
- **必须**手动执行飞行模式、弱网、杀进程、重启和时区切换场景。
- **必须**确认通知权限被拒绝时的产品降级行为。

退出标准：网络波动不丢草稿、不重复创建服务端事实，提醒时间符合本地时区。

### P6：质量与安全验收

预计：1 周。

工作内容：

- TalkBack 阅读顺序、内容描述、选中状态和动态字体测试。
- 浅色/深色对比度、小屏、横屏、平板和键盘避让检查。
- 冷启动、列表滚动、内存、网络耗电和后台任务检查。
- 检查 Token 存储、日志脱敏、备份策略、证书和服务端权限边界。
- 修复 P0/P1 缺陷，冻结 Release Candidate。

人工交互：

- **必须**进行人工探索测试；自动测试不能替代触控、视觉和系统权限检查。
- **必须**确认隐私声明、数据保留、设备撤销和日志策略。
- 建议由一名未参与实现的人完成独立验收。

退出标准：无 P0/P1 阻断缺陷，P2 缺陷有明确接受人和后续处理日期。

### P7：Beta 与成品交付

预计：1 周。

交付物：

- 签名 APK；需要商店发布时同时提供 AAB。
- Debug/Release 构建命令、版本号、commit、SHA-256 和签名验证结果。
- 安装、升级、回滚和卸载说明。
- 已知问题、隐私说明、服务端依赖和故障恢复手册。
- 上一个稳定版本的回滚包。

人工交互：

- **必须**由发布负责人保管正式签名密钥和密码，AI 不生成或托管生产密钥。
- **必须**由用户在目标手机上完成安装、升级、通知和核心路径验收。
- **必须**明确签署“接受发布”或列出阻断问题。

退出标准：验收人确认成品可交付，APK/AAB、文档和回滚包完整。

### P8：应用商店发布（可选）

预计：准备 2–3 个工作日；审核通常另需 3–10 个工作日，退审会延长。

人工交互：

- **必须**提供并操作 Google Play 开发者账号。
- **必须**确认应用名称、图标、截图、分级、隐私政策和数据安全表单。
- **必须**处理商店审核问答、测试账号和最终发布比例。

若只交付私人侧载 APK，本阶段可以跳过。

## 4. 人工参与总表

以下事项不能由代码或 Agent 单独完成：

| 人工角色 | 必须完成的事项 | 最晚时间 |
| --- | --- | --- |
| 产品负责人/用户 | 页面范围、Tools 内容、文案、认证方案、最终验收 | P1、P2、P7 |
| 真实设备测试者 | 触控、滚动、键盘、权限、提醒、弱网和升级测试 | P0、P5、P6 |

| 安全/隐私确认人 | Token、撤销、日志、数据保留和隐私声明 | P2、P6 |

| 商店账号所有者 | Google Play 素材、合规表单、审核和灰度发布 | P8（可选） |

每个“必须”节点若没有人工结论，对应阶段不能标记完成。

## 5. 自动化与验收命令

仓库内可自动执行：

```bash
npm.cmd run contract:mobile
npm.cmd run contract:calendar
npm.cmd run contract:captures
npm.cmd run contract:api
npm.cmd run verify:local
cd apps/android
gradlew.bat testDebugUnitTest
gradlew.bat lintDebug
gradlew.bat assembleDebug
gradlew.bat bundleRelease
```

自动化不能替代以下人工验收：

- 真机视觉、触控目标、键盘和系统栏。
- TalkBack、字体放大和深色模式。
- 通知授权、准时提醒、重启和时区变化。
- 真实网络、Cloudflare Access 和 Token 失效。
- APK 安装、覆盖升级、回滚和最终使用感受。

## 6. 风险与缓冲

- **认证方案未定**：P2 未完成时，不应并行实现大量远端页面逻辑。
- **真实环境不可用**：没有测试域名和受控身份会阻塞 P3–P7。
- **Room/KSP 工具链**：当前 Demo 为生成 APK 暂停 KSP；恢复缓存前必须解决
  Windows `R.jar`/Javac 权限或升级匹配的 Android 工具链。
- **范围膨胀**：Tools、新 Memory 能力和复杂离线写入可能增加 2–4 周。
- **设备碎片化**：至少预留 3 个工作日处理不同系统版本、厂商后台限制和通知差异。
- **商店审核**：审核时间不受工程团队控制，不应承诺固定发布日期。

建议在 P4、P6 各保留 2 个工作日缓冲；若认证方案变化或加入完整离线写入，
应重新估算排期。

## 7. 推荐交付节奏

- 每周提供一个可安装内部 APK。
- 每阶段结束记录：commit、APK SHA-256、自动检查结果、人工结论和已知问题。
- 人工反馈在下一个阶段开始前收敛，避免在 Release Candidate 后重做信息架构。
- 所有真实测试数据使用可追踪评估标签，并按现有治理流程清理。
