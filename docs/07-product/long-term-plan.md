# 远期规划方案书（Persona OS）

> 版本：v1.1
> 日期：2026-06-09
> 适用范围：个人工作台 -> 多端协同信息管道 -> 长期人格智能体

---

## 1. 规划立场

本方案明确：**系统大脑不是某个单一 LLM，而是 Cognitive Layer**。

也即：

`Memory + Persona + Workflow + Reasoning` 共同构成系统大脑；
其中 LLM 是推理引擎，不是全部大脑本体。

系统的 Telegram、Web、移动端、数据库、队列、推送器都属于外围神经系统和执行系统。

因此，本规划目标不是做一个聊天机器人，而是做一个可持续演化的 **Persona OS（人格操作系统）**。

---

## 2. 北极星目标

在 3-5 年内，建设一个具备以下能力的个人认知伙伴：

1. **连续人格**：保持稳定表达风格与价值观，不随渠道切换而失真。
2. **连续记忆**：能够追踪长期变化（兴趣、方法论、决策风格）。
3. **连续成长**：不仅陪伴，还能校正盲区，推动行动与创造。
4. **多端协同**：任何端输入都进入同一认知管道，输出按场景个性化。

---

## 3. 核心设计原则

1. **认知层中心化**：Cognitive Layer 统一决策，交互端只负责输入与呈现。
2. **人格分层化**：外显舒适、内核理性、记忆连续、结论可校正。
3. **事件驱动化**：以事件总线组织能力，降低耦合，便于扩展。
4. **记忆可审计**：画像、时间线、结论变化可追溯、可复盘。
5. **上下文节制**：按需召回，不做全量拼接，保证质量与成本。
6. **先验证后复杂化**：优先验证长期价值，再扩展 UI 和模型规模。
7. **逻辑分层与物理节制**：认知回路可多，首版调用链保持最简。

---

## 4. 目标架构

```
Persona OS
├─ Interaction Layer
├─ Orchestrator
├─ Cognitive Layer
│  ├─ Companion
│  ├─ Researcher
│  ├─ Critic
│  └─ Insight Engine
├─ Memory Layer
│  ├─ Profile
│  ├─ Goals
│  ├─ Timeline
│  ├─ Episodic
│  └─ Semantic
├─ Data Pipeline
├─ Engagement Layer
└─ LLM Router
```

## 4.1 Cognitive Layer（系统大脑）

- `Companion`：外显表达（舒适、理解、审美、允许沉默）
- `Researcher`：分析蒸馏（问题抽象、结构化、发现盲区）
- `Critic`：校正回路（反例、证据充分性、置信度）
- `Insight Engine`：主动洞察（趋势、异常、迁移、提醒）

说明：四者是**逻辑四回路**，首版默认**物理单回路**（单次调用内分步输出），避免成本和延迟线性放大。

## 4.2 系统协同层（外围系统）

- `Interaction Layer`：Telegram、Web Chat、未来移动端
- `Orchestrator`：请求编排、策略路由、任务调度
- `Context Builder`：按任务类型召回记忆并构建上下文
- `Memory Manager`：写入/更新/归档 profile/goals/timeline/episodic/semantic
- `Task Workers`：总结、分类、推送、日报、周报、提醒
- `LLM Router`：按任务切换推理引擎，不改变认知层协议

## 4.3 Memory Layer（记忆模型）

- `profile`：稳定人格与长期偏好（低频更新）
- `goals`：阶段目标与状态机（active/paused/done，进度可量化）
- `timeline`：关键认知转向与里程碑事件（中频更新）
- `episodic`：具体会话事件与场景片段（高频写入）
- `semantic`：抽象观点、方法论、主题知识（中频沉淀）
- `conversation log`：原始对话记录（审计与回放）

`goals` 是时间线之外的方向锚点，用于防止记忆体系退化为流水账。

---

## 5. 多端协同策略

### Telegram（高频主入口）

- 随手记录、转发、提醒、日报推送
- 追求低摩擦、秒级输入

### Web（低频控制台）

- 记忆编辑、画像查看、时间线回放、Prompt/Skill 管理
- 追求可管理、可解释、可复盘

### 移动端 App（后续阶段）

- 在 Web 成熟后再评估原生化需求
- 避免前期 UI 过重影响核心验证

---

## 6. 交互与留存层（Engagement Layer）

该层专门解决最大失败风险：**用户输入衰减**。

### 6.1 被动采集

- Telegram 转发/收藏即入库
- RSS/网页剪藏自动入库
- 低摩擦语音转文字

### 6.2 自动产出

- 每日摘要与次日建议
- 周报与兴趣迁移提示
- 目标偏离预警（基于 goals + timeline）

### 6.3 反馈触发

- 输出尽量可回复、可修正、可打分
- 通过反馈反向更新 profile/goals/semantic

---

## 7. 个性化输出框架

同一份输入，不同场景输出不同形态：

- 晨间：今日优先级 + 风险提醒 + 行动建议
- 晚间：完成回顾 + 偏差分析 + 次日调整
- 周报：主题进展 + 决策变化 + 下周计划
- 深度模式：概念建模、观点比较、反例推演

个性化逻辑基于以下变量：

- 用户阶段（探索/执行/创造）
- 当前目标（学习/交付/复盘）
- 时间窗口（日/周/月）
- 认知负载（简短提醒 vs 深度分析）
- 目标状态（推进/停滞/偏离）

---

## 8. 分阶段建设路线

## Phase 0（0-1 个月）：可用性验证

目标：证明“每天愿意使用”成立。

- Telegram Bot + Node.js + SQLite（当前实现）/ PostgreSQL（长期目标）+ 单模型
- 打通最小闭环：记录 -> 归档 -> 晚间摘要 -> 周报草稿
- 建立 goals + timeline 基础结构
- 首版采用逻辑四回路 + 单次调用分步输出

验收：连续 30 天可用，形成稳定输入习惯。

## Phase 1（1-3 个月）：人格分层上线

目标：从聊天升级为有认知分工的大脑。

- Companion/Researcher/Critic 三回路模板稳定
- Insight Engine 首版上线（下降趋势和目标偏离检测）
- 输出引入置信度和反例段落
- 形成“舒适 + 镜像 + 校正”组合能力

验收：用户可明显感知非回声室反馈。

## Phase 2（3-6 个月）：多端协同成型

目标：建立 Telegram + Web 双端协同。

- Web 控制台上线（记忆、时间线、配置、日志）
- 事件总线 + Worker 体系落地（总结/分类/推送）
- 中间数据层稳定（JSON snapshot + 结构化存储）
- Engagement Layer 完整化（被动采集 + 自动产出 + 反馈写回）

验收：跨端一致，记忆可视化与可编辑。

## Phase 3（6-12 个月）：多模型与长期复盘

目标：提升能力上限与长期稳定性。

- LLM Router（按任务路由不同模型）
- 图谱化记忆增强（主题关联、转向检测）
- 月度/季度认知演化报告自动生成

验收：能稳定输出“你过去如何变化”的高价值洞察。

---

## 9. 技术路线（当前仓库可演进）

1. 保持 Markdown-first，不打断现有 Obsidian 工作流。
2. 在 `scripts/` 外新增管道层（collect / normalize / enrich / deliver）。
3. 把现有同步脚本从“页面注入”升级为“事件和视图生成”。
4. 逐步引入 API 服务层（后端）承接记忆写入与任务编排。
5. 后续再接入队列与多模型路由，避免一次性过度设计。

### 9.1 单次调用分步输出建议

首版默认一个推理请求内完成四步：

1. `companion`：给用户可读回应
2. `researcher`：结构化蒸馏问题
3. `critic`：反例与置信度校正
4. `memory_patch`：建议写入的记忆变更

避免“一问多调”导致的成本、时延和链路脆弱。

## 10. 风险与控制

1. **输入衰减风险（最高优先）**：用户记录频率快速下降。
   控制：Engagement Layer（被动采集 + 自动产出 + 反馈触发）。

2. **回声室风险**：Companion 过强，Critic 过弱。
   控制：强制反例输出、置信度标注、证据不足提示。

3. **记忆污染风险**：临时情绪被写成长期特征。
   控制：短期记忆冷却窗口 + 周期性人工确认。

4. **工程复杂度风险**：多端与多模块导致维护失控。
   控制：事件总线解耦、先单模型再多模型、阶段验收。

5. **伪个性化风险**：输出花哨但不提升行动。
   控制：以完成率、采纳率、复盘命中率作为硬指标。

---

## 11. 成功指标（KPI）

- 使用连续性：7/30/90 天留存与活跃
- 管道效率：输入 -> 输出闭环完成率
- 行动转化：周计划执行率、延期下降率
- 认知价值：关键转向识别准确度、复盘采纳率
- 系统稳定性：跨端一致性、任务成功率、延迟与成本

### 11.1 认知连续性指标（核心）

- 是否能解释观点变化（从何时开始、为何变化）
- 是否能追踪兴趣迁移（主题热度和投入变化）
- 是否能识别长期模式（反复循环问题、有效策略沉淀）
- 是否能连接目标与行为（goals 与日常记录一致性）
